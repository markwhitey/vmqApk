# 省电心跳测试版

基线：itgoyo/vmqApk main，8a12b4746ee6e529b5f7d53275ea612887a2bd94。
目标：Android 14 小米手机在熄屏、未充电时保持 VMQFox 的在线心跳，不全天持有 CPU 唤醒锁，不强制亮屏。

## 改动

- 用 AlarmManager ELAPSED_REALTIME_WAKEUP + setExactAndAllowWhileIdle 替代 Thread.sleep(30000)，每60秒计划一次。
- 请求最长20秒，心跳部分唤醒锁最长25秒，完成立即释放。空闲时间不持锁。
- 保留收款通知前台服务；通知监听未真正连接时只请求重连，不虚报在线。
- 必须允许电池优化豁免。Android 14 AOSP 对用户白名单应用的闹钟放宽空闲限制；未豁免应用仍受 Doze 配额约束。小米 ROM 需要实测，不能保证与 AOSP 完全相同。
- HMAC-SHA-256 与 VMQFox V3 的 /api/monitor/heart、/api/monitor/push 一致；域名配置默认 HTTPS。
- HTTP 200 + 业务 code=200 才视为成功。付款网络重试沿用原时间戳/签名，最多3次，不构造新到账事件。

## 安装

测试包名 com.vone.qrcode.heartbeat，显示名 V免签·省电测试。可以与原版同时安装，原版不会被替换。

1. 安装前保存 VMQ 后台的监听配置二维码。不要把二维码、密钥或真实收款通知提交到 GitHub。
2. 在 Android 通知使用权中关闭原版 V免签，只启用省电测试版。检测到原版仍启用时，测试版会暂停，不发送心跳和收款事件。
3. 扫码或输入“域名/密钥”，点击“设置省电心跳权限”，允许电池优化豁免和精确定时；保留小米自启动权限。
4. 点击“检测心跳”，确认服务器接受；点击“检测监听”，确认收到测试通知。测试通知不会伪造付款。
5. 先做熄屏心跳测试；真实小额付款需要人工执行和核对，CI 与自动测试不会发起付款。

初次 Actions 构建使用 Android 调试签名，不包含生产签名密钥。不同 runner 的默认调试证书可能不同，后续测试包可能需要卸载测试版后重新安装；正式长期发布前应配置独立稳定签名。

## 真机验证

- USB/充电会改变休眠行为。自然熄屏测试应拔掉充电线，保持原网络，静置至少30–60分钟。
- 后台每次确认的心跳应接近60秒，关注最大间隔是否超过现有 VMQFox 的180秒离线阈值。
- 用 ADB 抓日志或设备空闲测试前记录插电/屏幕状态；强制 idle 的变更应测试后恢复。
- 关注 VmqHeartbeat 日志、手机页面的最后成功时间，以及服务器 lastheart，不能只看 HTTP 状态。
- 同等时长、相同网络/屏幕条件下比较 batterystats 中该应用的部分唤醒锁总时长；不能凭几十分钟电量百分比认定省电收益。
- 撤销通知使用权后，心跳闹钟必须停止；恢复授权后自动继续。

## 已知边界

系统精确定时仍可能被 ROM 限制。这是需要真机验证的实验方案；不以放宽 VMQ 服务端离线阈值掩盖问题。如果白名单下仍长时间延迟，再评估厂商推送按需唤醒，不回退到全天亮屏。
